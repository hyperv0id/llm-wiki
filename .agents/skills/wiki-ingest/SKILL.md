# wiki-ingest：单源摄入

用户要求把一份 `raw/` 源文件写进 wiki。页面 schema、frontmatter 字段、引用格式、文体与证据等级在根目录 `AGENTS.md`，动手前先读它；本技能只管流程。

## 硬约束：最小信息原则、一源一页与反刷分

- `raw/` 不可变，只读。判断源文件有错时在 `wiki/` 写更正页，不改源文件。
- **最小信息原则（源头拒载噪音）**：
  - **非必要不读全文**：禁止一上来通读整篇文本。**References（参考文献）100% 禁读；Appendix（附录）与 Related Work 默认不读**（仅当 Tier 1 论文正文核心公式缺失定义且明写见附录某节时，才按行号定点读该小节；绝不读附录跑分表）。
  - **非必要不核对微观指标**：禁止为了「核对数字」去算两位小数上的微观差距（如 `+0.18 / -0.04`）、禁止验算表格均值算术、禁止主动排查排版/印刷小瑕疵或占位符链接磨洋工。实验只抽定性结论、序关系与关键量级。
- **一源一页（禁跨页污染）**：`source-summary` 只服务单一源文件，`source_count` 固定为 `1`，正文只允许引用 `[^src-<本源>]`。新源入库时「更新既有页」**只允许修改 `concept` / `technique` / `analysis` / `entity` 页，严禁顺手改写其他论文的 `source-*.md`**（唯一例外：满足「矛盾处理」第 3 类，将旧源标为 `status: superseded` + `superseded_by`）。跨论文对照统一落到概念页或分析页。
- **建页准入门槛**：禁止为常规论文内部的自造模块缩写（如 `AGL`、`ASL`）新建 `source_count: 1` 的独立 `technique` 页。仅当某原语被 $\ge 2$ 篇论文复用/专门对比，或具有独立数学结构（改变复杂度阶数、独立定理或通用求解器）时，才建独立 `technique` / `concept` 页；否则写入 `source-<slug>.md` 并更新领域聚合页矩阵。新建页至少含 1 个 `[^src-*]` 引用。
- **反刷分禁令**：禁止整表照搬论文 Main Table，实验部分（`## 证据`）篇幅不得超过单页 20%。

## 职责与上下文隔离架构（Reader → Writer → Reviewer）

核心目标是两重隔离：**写 Wiki 的上下文看不见原论文的海量表格与行号噪音；审稿的上下文看不见原论文和 Writer 的写作过程**（真正做到读者盲测，避免运动员兼裁判）。根据当前运行环境（Harness）能力自动选择：

### 模式 A：多 Agent 协作（Harness 支持子 Agent 或 `omp -p` 独立调用时 —— 物理隔离）

1. **Reader Agent（切片脱水员：只读 `raw/` 核心切片，无 `wiki/` 视野）**
   - 先用 `rg -n` 扫描标题行号，只切取 **「Abstract + Intro 末段 + Method + Experiments 的 Setup 与 Ablation」**（跳过 References、Appendix、Related Work 及 Main Table 逐行明细）。
   - 向主 Agent 只回报一张 **$\le 400$ 字的《脱水内参卡》**，**严禁传回原始跑分大表、逐数据集两位小数对比，以及附录未核/排版瑕疵/口径验算碎语**：
     1. **人话大义**：不用公式与自造缩写，2–3 句话讲清它面对的具体失效模式、核心巧思与主结论。
     2. **去黑话配方与算子 $\Delta$**：用标准算子原语还原前向计算（Tier 1 附关键公式与张量形状变化）；相对最近邻基线，关键改动落在哪一步、有什么新假设或代价？
     3. **Ablation 真相**：消融表里掉点最狠的组件是什么？涨点来自主故事还是工程 trick？
     4. **定性结论与论文自述边界**：在主任务上是真超越还是低开销逼近（只给代表性量级，不列细表）？在哪些设置下没赢？论文自己承认哪些适用范围？
2. **Writer Agent（主 Agent / 图谱架构师：禁读 `raw/` 原文，只管 `wiki/`）**
   - **硬隔离：主 Agent 全程禁止打开 `raw/` 原文**，从物理上断绝抄表、算两位小数微差和句中插行号的可能。
   - 仅凭 Reader 回报的《脱水内参卡》+ 读取 `wiki/index.md` 及 2–3 个关联 Wiki 页，执行下方「合入流程」的第 2–5 步落盘。
3. **Reviewer Agent（独立盲审员：只读落盘后的 `wiki/` 新/改页面，禁读 `raw/`，不继承 Writer 上下文）**
   - Writer 完成页面落盘且通过 `lint.py` 硬结构检查后，启动**全新上下文**的 Reviewer 子 Agent，只传入本次新建/修改的 `wiki/` 文件路径和下方「独立盲审清单」。
   - Reviewer 必须输出**盲读复述 + 问题原句清单 + 裁决（`PASS` / `REVISE`）**，禁止只答 Yes/No。
   - 若裁决为 `REVISE`：Writer 按意见修改后，**重开独立 Reviewer 复审**（最多 2 轮）。未获 `PASS` 不得提交。

### 模式 B：单 Agent 渐进漏斗（Harness 无子代理功能时 —— 切片与阶段隔离）

当环境不支持子 Agent 时，单 Agent 必须通过**分阶段读取与显式封存**模拟上述隔离：

1. **摸边界（不读正文）**：`raw/*.pdf` 先 `pdftotext -layout` 转文本；先用 `rg -n` 找出各章行号，把 References、Appendix、Related Work 划为禁读行区间。
2. **读核心切片并产出《脱水内参卡》**：只按行号读取「Intro 末段 + Method + Ablation」，立即在当前思考步内写出上述 $\le 400$ 字的《脱水内参卡》。
3. **封存原文并落盘**：《脱水内参卡》产出后，**严禁再调用读取工具回翻 `raw/` 原文查表格或抠细节**，直接切换到图谱合入阶段。
4. **降级盲审**：落盘后切至「未看过原论文的读者视角」，按下方「独立盲审清单」强制先挑出至少 3 处最晦涩、电报化或疑似挑刺/抄表的原句逐一核修，不得以 Yes/No 自评一笔带过。

## 合入流程

1. **获取《脱水内参卡》**：按模式 A（子 Agent 回报）或模式 B（单 Agent 切片坍缩）拿到脱水结论。
2. **分级分流（Triage）与检索索引**。读 `wiki/index.md` 定位已有相关页面，按三档决定入库深度（用户已指定则遵从）：
   - **Tier 1（基石 / 新算子 / 强理论或颠覆性实证）**：建/更独立机制页，写完整分阶段 `aligned` 维度块与三行实验判词。
   - **Tier 2（常规方法 / 已有积木的新组合）**：**轻量化入库**——只建 `source-<slug>.md`（写清去黑话算子配方与三行实验判词），并在所属领域 `concept` 页对比矩阵里加一行；**不为其内部拼装子模块新建独立 `technique` 页**。
   - **Tier 3（边缘参考 / 弱证据预印本）**：仅建简短 `source-<slug>.md`，在相关页末尾挂一行引用。
3. **跨文关系挂载与既有页更新**：
   - 更新既有页仅限 `concept` / `technique` / `analysis` / `entity`（**禁止修改其他论文的 `source-*.md`**）。
   - 新建交叉链接时，标明四类有向关系之一，禁止堆砌裸链接：**同构/退化特例**、**瓶颈接力 $\Delta$**、**槽位关系**（同槽位互斥 vs 跨槽位正交）、**实证复现对齐**（新源重跑既有基线出现定性排名反转时回填）。
   - 若涉及的聚合 `concept` / `analysis` 页已关联 $\ge 4$ 篇论文，直接维护其**正交设计决策轴二维矩阵**，禁止继续追加「每篇一段」的流水简介。
   - 发现定性论断冲突按「矛盾处理」执行。
4. **新建机制/概念页（仅 Tier 1 或满足建页门槛时）**：文件名小写、连字符、无空格。Tier 1 模型类页按「数据流与维度变换」写分阶段 `aligned` 块；实验部分严守 `AGENTS.md` 的「三行判词」与 $\le 20\%$ 篇幅上限，**不回原文搬表、不核对微观小数差异**。
5. **写 `source-summary`**：`wiki/source-<slug>.md`，`type: source-summary`，`source_count: 1`（仅引用 `[^src-<slug>]`），约 300–500 字，按固定轻量骨架组织：
   - **首段（无开篇 callout）**：直接用 3–5 句不含公式与坐标的纯人话讲清「旧做法卡在哪 → 本文核心巧思 → 主结论」。**严禁在开篇放 `> [!note] 出处口径` 或「来自用户、未核实」等免责语**；作者/年份/venue/arXiv 等出版信息压成页尾单行元信息或放入 frontmatter。
   - **`## 核心做法`**：只写「为什么这么做 + 标准算子组合」。论文自造缩写首次出现必须先译成标准算子再括注原名。**严禁堆公式推导、超参范围网格、以及参数量/MACs/显存/延迟等工程数字**（这些属于 Tier 1 机制页或证据段）。
   - **`## 证据`**：固定 3 条判词（1. 定位与主结论；2. 真实涨点归因；3. 证据缺口与负结果），只写定性趋势与量级，**严禁罗列逐数据集三位小数对比、严禁写 Table/附录坐标与口径验算**。
   - **`## 局限`（可选，仅论文明确自述时写）**：只写论文明确自述的适用边界。**严禁把 agent 的挑刺写进正文或局限**（如 URL 占位符、缺墙钟/FLOPs 数字、附录未核、版本存疑）；确需留痕的核查备注只写进 `ingest-reports/`。
   - **`## 相关页面`**：**图谱关系只在此处写一次**（正文不另设重复的「图谱关系 / 有向关系对照」段）。每条最多挂 2 个目标，写明有向关系类型 + 半句差异说明；严禁无说明的裸链接拼接（如 `[[a]] · [[b]]`）。
6. **两级门禁校验（硬结构 + 独立盲审）**：
   - **第一步：硬结构检查**（仅验证 frontmatter、引用闭环、一源一页、断链等确定性不变量）：
     ```bash
     python3 scripts/lint.py --text --fail-on-severe <本次新建或修改的 wiki/*.md>
     ```
     **注意：`lint.py` 不做自然语言质量判断，过了 `lint.py` 绝不代表文案合格。**
   - **第二步：独立 LLM 盲审**（真正的文案质量门禁）：按下方「独立盲审清单」运行 Reviewer Agent，直到拿到 `PASS`。
7. **更新 `wiki/index.md`**：按 frontmatter `type` 分五段（Sources / Entities / Concepts / Techniques / Analyses），段内字母序，每页仅一条。
8. **更新 frontmatter**：所有被改页面刷新 `last_updated`，重算 `source_count`，调整 `confidence`。
9. **写 `ingest-reports/YYYY-MM-DD-<slug>.md`**（格式见下，含 Tier 定级说明；如有出处/版本待核等流程备注写在这里，不写入 wiki 正文）。
10. **追加 `wiki/log.md`**：

    ```
    ## [YYYY-MM-DD] ingest | {标题}
    {1 段：Tier 等级 + 源解决了什么问题、去黑话机制与定性实验判词；有证据缺口直接写}
    创建的页面：[[page1]], [[page2]]
    更新的页面：[[page3]]（一行改动摘要，source_count 1→2）
    ingest 报告：[[ingest-reports/YYYY-MM-DD-slug|WHY 报告]]
    ```

11. **提交**：dashboard 路径由 `server.py` 自动 commit；手工路径以 `ingest <标题>` 作为 commit message 提交 `raw/`、`wiki/`、`ingest-reports/`。

## 独立盲审清单（Reviewer Agent 协议）

Reviewer 仅读取本次新建/修改的 `wiki/` 页面，**严禁读取 `raw/` 原文**，按以下三项逐条输出：

1. **盲读复述测试（必答）**
   - 不看原文、遮住公式，仅凭目标页用 2–3 句自然语言复述「旧做法的矛盾 → 核心巧思 → 实验主结论」。
   - 凡是复述不出来，或遇到**未解释即引用的术语/论文自造缩写**，一律判 `REVISE` 并贴出卡壳原句。
2. **对抗式体检（逐项核查，有问题必须贴出原句与改法）**
   - **开篇免责 / 甩锅**：正文开头是否放了「出处口径」callout、文件路径、版本号核实或「来自用户、未核实」等免责语？
   - **电报化与去黑话**：`source-summary` 的做法/配方段是否堆砌了公式推导、超参范围网格或参数量/MACs/显存/延迟数字？自造缩写是否只写「论文称 XXX」而未还原为标准算子？
   - **实验三行判词**：证据段是否超过全文 20%、是否变成逐数据集三位小数流水账、是否夹带 `Table`/`Appendix` 坐标或口径验算？是否点出了 Ablation 里真实涨点来源？
   - **局限边界**：局限段是否混入了 agent 挑刺（如 URL 占位符、缺墙钟数字、附录未核）而非论文自述？
   - **图谱关系与边界**：图谱关系是否在正文和 `## 相关页面` 重复写两遍？单条关系是否串了 $>2$ 个目标？是否存在无说明裸链接拼接？本次改动是否顺带污染了其他论文的 `source-*.md`？
   - **措辞纪律**：是否出现营销/体育化措辞、禁用词或 emoji？聚合页（$\ge 4$ 篇源）是否仍按论文逐段报菜名？
3. **裁决输出**
   - 输出 `PASS` 或 `REVISE`（附按条排列的必改清单）。只要存在任一实质问题，必须判 `REVISE`，不得放水。

## 数据流与维度变换（Tier 1 模型类页面必用）

讲模型前向传播时，**禁止用表格罗列张量清单或逐步形状变化**——表格是线性的，表达不了并行支路、汇合过程，也看不出矩阵乘法消掉了哪一维。改用「分阶段计算图块（staged computation blocks）」。

### 1. 维度符号速查

「数据流」小节开头用一到三行交代超参的物理意义，不列中间张量的大表：

> **维度符号**：$N$ 序列长度（token 数）；$d$ 单头通道维；$m$ landmark 数；$k$ 每个专家选中的 token 数。

形状统一记作 $[\text{行}, \text{列}]$，与论文记号一致。论文按单头书写、本页按多头展开时，推断部分标 `[INFERENCE]`。

### 2. 按前向拓扑分阶段

- 一个阶段一个小标题，编号加动词短语：`### Stage 1 · 造 landmark query`。
- 并行支路在同一阶段内用无序列表拆开，各占一个公式块：`**支路 A：共享专家（常开，宽 $m$）**`、`**支路 B：形变专家（稀疏，宽 $k$）**`。支路前先交代它读哪些张量、形状是什么。
- 支路汇合单独成阶段，写清合并方式（拼接、按打分路由、online softmax 合并等）。

### 3. 每个公式块的四要素

```latex
$$\begin{aligned}
S^{kv} &= K^{\top}\tilde{Q}/\sqrt{d} && \text{// } [N, \bcancel{d}]\times[\bcancel{d}, m]\to[N, m]\ \text{——消去 } d\text{，每列是一个 landmark 对全部 } N \text{ 个 key 的打分}\\
\mathcal{I}_i &= \operatorname{Top}_k\!\left(K^{\top}\tilde{q}_i\right) && \text{// } [N, m] \xrightarrow{\text{沿 } N \text{ 维逐列 Top-}k} [k, m]\ \text{——每组 } k \text{ 个 key 下标（取值 } 1..N\text{）}
\end{aligned}$$
```

左侧放张量符号与公式，右侧 `&& \text{// }` 注解必须同时给出**维度变换**和**一句话物理含义**；多行用 `\\` 对齐，注解内部不换行，物理含义用 `\ \text{——}` 接在维度变换之后。

### 4. 维度标注定式

| 操作 | 写法 |
|---|---|
| 矩阵乘法 | 用 `\bcancel{}` 标出被消去的维度：`[N, \bcancel{d}]\times[\bcancel{d}, m]\to[N, m]` |
| 规约 / 池化 / 采样（softmax、Top-$k$、ArgMax、AvgPool） | 带文字的箭头写清沿哪一维操作：`[N, m] \xrightarrow{\text{沿 } N \text{ 维逐列 Top-}k} [k, m]` |
| 索引 / 重排（Gather、ArgSort） | 标明索引张量的形状如何作用于原张量：`[d, N] \xrightarrow{\text{按 } \mathcal{I}\in[mk] \text{ 索引列}} [d, mk]` |

### 5. 表格的用途

表格只承载**跨方法设计决策对照矩阵**或**精简关键数字对比（单篇机制页原则上 $\le 5$ 行）**，既不承载张量形状，也不照搬论文完整 Main Table。完整 Tier 1 标杆范例可直接参照 `wiki/mita-attention.md`（架构/算子类）与 `wiki/distdf.md`（理论/损失函数类）。

## 矛盾处理

新源与既有论断冲突时，按冲突性质三选一，不得静默覆盖：

- **新源更新且证据强**（多源支持、时间更近、方法更直接）：旧论断移入 `## 历史论断`，正文写新论断，注明日期与取代关系。
- **日期相近或新源证据弱**（单一源、preprint、口径不明）：正文建 `## 争议`，并列两种论断，页面 `status: disputed`，写清待解决点。
- **新源明确反驳旧源**：旧 source-summary 页设 `status: superseded` 与 `superseded_by: [[新页]]`。

三种情况都追加 `wiki/log.md`：

```
## [YYYY-MM-DD] contradiction | {页面} | {情况 1/2/3}
{旧论断} vs {新论断}。解决方案：{所选情况}。
```

## WHY 报告格式

```markdown
# Ingest 报告：{source_name}

- **分级**：Tier 1 / Tier 2 / Tier 3（一句话定级理由）

## 创建
- wiki/page.md — WHY：一行理由

## 修改
- wiki/page.md — WHY：一行理由

## 新建交叉链接（标明关系类型）
- [[a]] ↔ [[b]]（同构 / 瓶颈接力 Δ / 同槽位互斥 / 跨槽位正交 / 复现对齐）

## 核查备注（可选，不写入 wiki 正文）
- 出处版本、链接状态或待后续复核的流程信息
```
